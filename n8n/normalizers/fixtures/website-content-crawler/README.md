# Website source contract examples

`m05-local-contract.json` is a hand-authored local example, not an Apify or Firecrawl capture. `website.test.ts` and `native-m05-website.test.mjs` use labelled local inputs. Real ordinary HTML, JavaScript-heavy, empty-map and source-error observations remain unverified until the separately estimated M05 dev packet is authorized.

Official contracts checked on 28 October 2026:

- [Firecrawl v2 map](https://docs.firecrawl.dev/api-reference/endpoint/map): `links` contains objects with `url`. Map is one credit per call. Discovery is not a source-exhaustion guarantee. The planner explicitly sets 500 daily / 2,000 backfill links, same-host ownership, `includeSubdomains:false`, `sitemap:include`, query ignoring and a 60-second timeout. A saturated or empty map does not mark history complete.
- [Firecrawl map behavior](https://docs.firecrawl.dev/features/map): sitemap, search and previously crawled links can discover most links. Complete observed-map processing is distinct from complete website history.
- [Website Content Crawler input](https://apify.com/apify/website-content-crawler/input-schema) and [actor documentation](https://apify.com/apify/website-content-crawler): fixed requested URLs, no link expansion, at most 200 URLs per actor input, robots respected, strict TLS, no cookies/custom headers, no CAPTCHA session rotations, no files/video/screenshots, no summarization. The single adaptive retry applies only to thin public pages; blocked/private/error pages are failed. An approved pinned build and a complete measured-use estimate are still required before a start.
- [Current Run Actor API](https://docs.apify.com/api/v2/actors-runs-post) corrects the earlier PPU assumption: `maxTotalChargeUsd` caps the total run charge for all pricing models. Website starts now send the reviewed descriptor cap, at most USD0.40 here, and require an exact native response acknowledgment with `isMaxTotalChargeUsdSetByUser:true`. A valid returned actor ID is durably registered before stopping on a missing or contradictory cap acknowledgment; no further start or closure is allowed until the known run is reconciled. `maxItems` applies only to charged pay-per-result items and does not limit returned items. PPU website requests therefore omit that query parameter; exact requested URLs, actor input `maxResults`/`maxCrawlPages` and callback dataset guards independently bound the data scope.
- [Current public actor pricing](https://apify.com/apify/website-content-crawler/pricing): on this review date, CU rates are USD0.20 Free/Starter, USD0.16 Scale and USD0.13 Business; the actual account plan and separate proxy/storage/transfer usage still need their bounded live readback. Older overview or checked-in price-book amounts are dated estimates, not proof of current billing. At fixed1GB/600seconds, each deliberate start uses at most one-sixth CU of compute. This resource-based quote is separate from the API total-charge cap and its required native acknowledgment; no live acknowledgment or actual charge has been observed by these local tests.
- [n8n Code node libraries](https://github.com/n8n-io/n8n-docs/blob/main/docs/reusable-content/.gitbook/includes/integrations/builtin/core-nodes/code-node.md): Cloud Code does not provide arbitrary imports. The native workflow performs I/O through secured HTTP Request4.5 nodes. Serialized transitions run in local tests without `URL`, packages or network globals. Their strict public-URL subset is tested against the canonical Node helper; literal dot segments are refused.

Identity is the existing SHA256 first32 of the canonical requested URL, preserving path case. A conflicting page canonical/loaded URL fails that requested page. Unknown publication is `null`; backfill content carries `payload.backfill:true`. Payloads contain projected public text/title and provenance only, rather than actor headers, cookies, full HTML or unknown metadata. Vimeo/YouTube links are references, never instructions to fetch video.

WF-21 claims `website_work_page` and fallback `website` identities separately under one owned run. Firecrawl attempts use the trusted price-book credit value; the local amount is an accounting estimate, not a provider billing receipt. URL diff is chunked at the existing 1,000-URL RPC bound, includes new/failed rows under the owned claim, and the daily redesign guard refuses more than 30 new pages when they exceed 80 percent of mapped project URLs. Callback ingestion owns page marking, measured actor costs, partial failures and the atomic thin-retry completion barrier. Every requested URL is represented once, including missing results as failures. Unknown starts remain reconciliation boundaries; no second actor is silently started.

For an explicitly bounded representative capture, `source_options:{map_limit:100,max_new_urls_per_account:3}` narrows the defaults. All observed owned URLs are diffed first. The stable first three canonical mapped project candidates are then intersected with pending URLs; this fixed window prevents an unchanged rerun from silently choosing the next three deferred pages. Exact candidate URLs, pending/selected/deferred counts and cap saturation are reported as `candidate_subset`, with `backfill_done:false`. Remaining URLs stay new/failed and are not treated as history completion. A changed candidate set remains subject to the gateway/database's cumulative distinct-URL allowance per account/approval; the local selector is not spending authority. Default uncapped-product selection remains all observed project URLs within the existing mode bound.

The checked-in WF-21 blueprint remains inactive and explicitly blocked until actual Firecrawl credential metadata is supplied. It contains no fabricated credential ID, public capture, active schedule or hosted acceptance claim. The runnable builder accepts a separate explicit dev Header Auth reference and preserves the existing Apify and restricted Machine bindings.
