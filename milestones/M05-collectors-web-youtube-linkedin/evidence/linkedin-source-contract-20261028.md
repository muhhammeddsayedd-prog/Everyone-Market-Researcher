## Implemented local behavior

- `linkedin.mjs` validates exact claimed company URLs/UUIDs, rejects fuzzy display-name ownership, groups posts by actual date cutoff, and constructs finite public INPUTs. No source cursor is invented for posts. Employee descriptors pin a trusted capture date and query/page bounds.
- `linkedinPosts.js` projects company-authored post IDs/URLs, ISO or millisecond dates, caption/Arabic hashtags and validated engagement counts. Zero likes does not fall through to a reaction sum. Rich profile/media payloads are not persisted. Unknown owner, conflicting URL/slug, impossible/future dates, unmatched rows, cap saturation and unverified repost shapes fail closed. Backfill remains incomplete: dataset length/EOF is not a company-history source-stop proof.
- `linkedinEmployees.js` returns exactly `{public_id,name,title,location}`. No raw employee payload enters item ingestion, exports or snapshots. Verified singleton registered-query context is described as **query evidence**, not proof of employment or a complete roster; no company-name guessing occurs. Contradictory identities, ambiguous mixed-company output and output overflow fail. Coverage remains partial, so observed counts are not full company headcounts.
- Partial snapshots never infer departures/joins. Pure complete-comparison logic is available only for independently established complete observations; that is not a provider capability claim. Exact same-date canonical replay is a no-op; different observations return a conflict and cannot overwrite earlier data. Existing people/human corrections require protected RPC handling in the owning migration; the normalizer does not update people.
- `linkedin-run.mjs` uses fixed start/claim/launch/register/close_registration ports. SQL pass is `primary`; actor identity distinguishes posts/employees. Launch binds exact INPUT and employee snapshot date. A non-replayed server launch permit, pinned build and bounded descriptor precede every injected actor start. Unknown paid outcome/lost registration receipt stops for reconciliation without another POST, guessed finish or claim release. All registrations close before dispatch returns. A validated owned close receipt reports `completed` with the actual success/partial/failed status when callbacks already settled; otherwise it reports `awaiting_callbacks`. Foreign run summaries, inconsistent completion flags and malformed statuses require reconciliation. The driver never ingests employee data.
- `native-m05-linkedin.mjs` and `build-native-m05-linkedin.mjs` compose the same planners into supported HTTP Request4.5 nodes using existing actual credential references. New `blueprints/WF-18.json` and `WF-18b.json` are explicitly synthetic local definitions, inactive/unpublished, without schedules, error-handler publication or execution payload saving. Typed gateway/actor transitions and full registration barrier execute locally without URL/require/fetch/package globals. They are not Cloud-saved exports; historical `n8n/workflows/` files are unchanged.

## Required integration and precise live gaps

The root-owned restricted gateway/callback must attest actor owner/build/INPUT/usage, route post groups through existing ingestion, and route only projected employee people/coverage through the owned snapshot operation. It must enforce live approval/budget, claim ownership, privacy, source coverage and cost-once settlement. The driver itself supplies no live authorization.

The [posts README](https://apify.com/harvestapi/linkedin-company-posts) currently demonstrates a profile post, not a real company repost/video. Outer repost ownership/ID and original-author context, company media/thumbnail field shapes and per-target history-stop evidence remain unproved. The local implementation does not guess them or present absent media as verified coverage. Repost/quote INPUT inclusion is implemented; successful normalization of unverified repost shapes is not claimed.

The [employees README](https://apify.com/harvestapi/linkedin-company-employees) shows a rich Full-mode profile; its currentPosition example contains a company name only. Exact Short-mode current-company identity and per-company source exhaustion metadata still need a bounded approved live example. The README's pagination-code sample names a different actor, so its `_meta.pagination.pageNumber` shape is not silently transferred here. The documented2500 search-query ceiling and our200-person bound do not establish the whole roster or global impossibility of further acquisition.

The draft `left_company` computation from two arbitrary capped snapshots is unsafe; the local contract suppresses it unless comparable completeness is independently established. Likewise, a succeeded zero-result actor cannot establish a complete empty company if rows were mismatched, filters/caps applied or source-stop evidence is unavailable. No new capture, source, recurring activity, notification or production operation is authorized by this note.
