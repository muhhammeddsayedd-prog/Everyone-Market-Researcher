# YouTube source contract — local M05 implementation

28 October2026. Official public documentation research and local tests only. No key, saved credential, provider-data request, hosted migration, workflow save/activation or capture was used. Synthetic fixtures do not establish native Cloud or real-provider acceptance.

## Verified official API

- [channels.list](https://developers.google.com/youtube/data/reference/rest/v3/channels/list): `part=id,contentDetails`, exactly one of `id`, `forHandle`, `forUsername`; read `contentDetails.relatedPlaylists.uploads`. `/c/alias` is not a documented `forUsername` mapping. Reuse genuine M02 IDs; do not guess an unresolved source or revisit D-27 exclusions.
- [Channel resource](https://developers.google.com/youtube/data/reference/rest/v3/channels): the returned uploads playlist is a string ID. Its public contract does not guarantee a `UU` prefix or a channel-ID suffix transformation. Both drivers preserve the actual bounded opaque value, bind channel and playlist independently in saved cursors, and verify each playlist/video owner's channel. Synthetic regressions cover a differing returned ID and cross-channel cursor rejection.
- [playlistItems.list](https://developers.google.com/youtube/data/reference/rest/v3/playlistItems/list): returned uploads playlist, `part=snippet,contentDetails,status`, at most50 entries, opaque `pageToken`/`nextPageToken`. The saved cursor binds channel, playlist, page width and token. Repeated tokens, foreign identities and empty nonterminal pages fail closed. No documented chronological guarantee was found: a known ID or one old timestamp cannot prove source exhaustion. Only actual EOF completes this first slice; a page cap remains partial with its next cursor.
- [videos.list](https://developers.google.com/youtube/data/reference/rest/v3/videos/list): batch no more than50 requested IDs; `part=snippet,contentDetails,statistics,status`. `maxResults` is not supported with the ID filter. Join by requested ID and exact owner channel, accept only public status, and retain unavailable IDs separately. Known items in the thirty-day window remain in normalization/ingestion for metrics refresh. Do not fetch comments, captions, files or analytics.
- [Google system parameters](https://docs.cloud.google.com/apis/docs/system-parameters): existing `X-Goog-Api-Key` Header Auth is supported. Old Query Auth/key-in-URL examples lose to the existing binding decision. Requests use fixed `www.googleapis.com`, strict TLS and no redirects; no OAuth/private filters or `search.list`.
- [Quota](https://developers.google.com/youtube/data/determine_quota_cost): each of these three list methods costs1 unit; invalid requests and additional pages also cost quota. Quota resets at midnight Pacific. The connected driver requires an atomic quantity1 reservation before each HTTP attempt, plus the existing8000-unit safety ceiling. Reservations are separate from the USD0 cost-ledger quantity and must not be summed twice. Unknown network outcomes are conservatively charged. A Pacific-day rollover stops new calls rather than charging a new day under the prior day. No fallback is enabled for quota/auth/rate-limit failures.

## Explicit source limitations and deviations

The existing `duration<=60` item-type rule is preserved as a **heuristic**, with `payload.shorts_classification=duration_heuristic_unverified`. It is not actual Shorts identification. [Current official policy](https://support.google.com/youtube/answer/15424877) includes square/vertical videos up to three minutes under date-dependent rules; the public Data API has no `isShorts` property, and duration alone cannot recover those facts. The fallback adapter's synthetic `type=shorts` mapping is an actor-contract example, not verified capture. Do not claim AC4 real Shorts coverage from the heuristic.

The primary normalizer projects metadata rather than persisting arbitrary provider fields. Stats that are hidden, invalid or larger than safe integer precision stay null; dates, ownership and source identity are validated. Caption text is bounded8000 characters, credits1500, and canonical ingress batches are limited to100 items with1KiB reserved inside the1MiB UTF8 request ceiling for the fixed gateway envelope. No download/auth/cookie fields survive projection. Thumbnail URLs are public YouTube image-host projections, not permission for a future consumer to bypass DNS or redirect checks.

The M04 `ops.set_account_external_id` implementation is Vimeo-only despite draft M05 text calling it reusable. M05 needs the separately authored forward resolver/claim/gateway contracts. The collector itself opens no database connection and carries no administrative credential.

`streamers/youtube-scraper` remains blocked/unreachable. Its pure normalizer is local contract coverage; a current pinned actor/build/input/pricing review, appropriate examples and a separately approved M05 live packet are still needed. No transcript, subtitle, AI or stream add-on is authorized.

## Implemented local path

`youtube.mjs` performs bounded resolution, uploads paging, owned-video joins, normalization, attempt accounting and truthful EOF/cursor outcomes through injected native HTTP. `youtube-run.mjs` connects fixed dev selectors to start/claim, quota reserve, resolve, byte-batched ingestion, per-account reporting, cost and finish ports, using stable request IDs. Completion requires the matching parent ID and actual database summary status; it cannot substitute the requested status. Lost gateway/quota receipts produce reconciliation without another run or guessed release/finish.

`native-m05-runtime.mjs` and `build-native-m05.mjs` execute the same path using supported native HTTP4.5, Code2, IF2.3 and workflow-input1.3 nodes. Code nodes perform no I/O/imports; typed `m05.*` requests and public YouTube requests have separate credentials. The generated WF-13 blueprint is inactive, does not save execution/pinned data, has no schedule and binds no unpublished error handler. It is a local blueprint with labelled fixture selectors, not a saved native export or deployment. Existing actual M03/M04 workflow exports remain unchanged.
