After CloudA passes, the sealed helper supports:

```powershell

& '.\scripts\n8n\windows\Invoke-M03GW01Bypass.ps1' -Mode ReconcileRevoked
```

It generates a new32-character alphanumeric token into the new encrypted
ProtectionBypass handoff before the one supported API request. Generate uses
only the owned note and secret; it never updates an existing default. A passed
ordinary create/readback requires the owned note, creation time and explicit
`isEnvVar:false`. Missing `isEnvVar` means default and cannot pass that gate.
Never Generate again after an attempt. Ambiguous creation has GET-only
reconciliation. Revoke sends only the same owned secret with `regenerate:false`;
existing bypass entries and Deployment Protection stay untouched.
The finite readback reports only `absent`, `true`, `false` or `not_boolean` for
the owned flag, verified ownership metadata booleans and counts of other entries.
Omitted flags count as selected defaults according to the official schema; they
are never normalized to false. A successful Create records valid scope/note/time
provenance before evaluating this gate. A later GET without that successful
creation receipt cannot manufacture it or adopt an unknown POST outcome.

The approved first-entry exception requires a source-sealed
`gw01-bypass-known-create.json`: the owner's observation of the original
successful CLI child, bound to the same original intent, project, note and tool
reference. This is not a saved server response. `RecoverSoleCreated` performs
one GET and requires matching owned metadata, creation within the original
bounded interval, true/absent default flag, and zero other entries. It writes
`out/gw01-bypass-recovered-sole.json` as a separate, immutable GET observation;
it never creates a historical successful-POST receipt. Output distinguishes
`soleOwnedDefaultVerified:true` from `nonDefaultVerified:false`.

Recovered-sole revocation requires another matching GET with zero other
entries. It writes a durable revoke intent before the single PATCH, then
requires a final GET with an explicit empty bypass object before deleting the
encrypted handoff. A lost acknowledgment blocks another `Revoke`; use the
GET-only `ReconcileRevoked` continuation. Missing/null maps, surviving own or
other entries, changed creation times and unverified child closure retain the
handoff and stop cleanup. No mode transfers default selection or updates
another entry.

Automation bypasses are project-wide platform credentials. The worker's exact
preview/project/branch/deployment/window binding supplies the narrower application
boundary. The dedicated bypass is used only in a header, never a query/cookie.

Supported API contract: [Vercel protection-bypass endpoint](https://vercel.com/docs/rest-api/projects/update-protection-bypass-for-automation)
and [automation bypass semantics](https://vercel.com/docs/deployment-protection/methods-to-bypass-deployment-protection/protection-bypass-automation).
